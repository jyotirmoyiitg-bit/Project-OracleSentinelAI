# Oracle Database Common Errors & Resolutions Reference Guide

---

## Domain 1: Database Startup, Shutdown & Instance Lifecycle

### ORA-01034: ORACLE not available
- **Description:** The database instance is not currently running or memory segments have not been allocated.
- **Probable Causes:** The instance was shut down, crashed unexpectedly, or your `ORACLE_SID` / environment variables point to an inactive instance.
- **Resolution:**
  1. Verify your environment variables: `echo $ORACLE_SID` (Linux) or `echo %ORACLE_SID%` (Windows).
  2. Connect locally as SYSDBA: `sqlplus / as sysdba`.
  3. Start the instance: `STARTUP;`.
  4. Inspect the alert log (`alert_<ORACLE_SID>.log`) if the startup fails.

### ORA-01078: failure in processing system parameters
- **Description:** Oracle encountered an error while attempting to read the parameter initialization file during startup.
- **Probable Causes:** The initialization file (`init<ORACLE_SID>.ora` or `spfile<ORACLE_SID>.ora`) does not exist in `$ORACLE_HOME/dbs` (or `%ORACLE_HOME%\database`), has syntax errors, or contains unrecognized parameter values.
- **Resolution:**
  1. Confirm the presence of the SPFILE or PFILE in the default directory.
  2. Specify the explicit PFILE if located elsewhere: `STARTUP PFILE='/path/to/init.ora';`.
  3. If syntax or parameter errors are present, create a PFILE from the existing SPFILE (`CREATE PFILE FROM SPFILE;`), fix the bad line with a text editor, and restart.

### ORA-01081: cannot start already-running ORACLE - shut it down first
- **Description:** A `STARTUP` command was issued on an instance that is already mounted or open.
- **Probable Causes:** Attempting to start an instance that has not been shut down.
- **Resolution:** Check the status via `SELECT status FROM v$instance;`. If a restart is required, perform `SHUTDOWN IMMEDIATE;` followed by `STARTUP;`.

### ORA-01090: shutdown in progress - connection is not permitted
- **Description:** New connections are rejected because the database is in the process of shutting down.
- **Probable Causes:** A previous `SHUTDOWN` command is waiting on pending transactions or disconnected user sessions.
- **Resolution:** Wait for existing transactions to roll back or terminate cleanly. If the shutdown hangs indefinitely, issue `SHUTDOWN ABORT;` followed by `STARTUP;` and `SHUTDOWN IMMEDIATE;` to complete a clean recovery cycle.

### ORA-01092: ORACLE instance terminated. Disconnection forced
- **Description:** The background processes terminated abnormally, forcing all client connections to close.
- **Probable Causes:** Fatal background process failure (PMON, SMON, DBWn), severe corruption in control files or undo segments during startup/mount.
- **Resolution:** Check the alert log and background trace directory for the underlying error (often pre-dated by an `ORA-00600` or `ORA-07445`). Fix the indicated underlying corruption, then restart the database.

### ORA-01109: database not open
- **Description:** The operation requires an open database, but the database is only in `MOUNTED` or `NOMOUNT` state.
- **Probable Causes:** The instance mounted successfully, but failed to open (often due to missing datafiles or redo logs), or startup was halted at the mount stage.
- **Resolution:** Execute `ALTER DATABASE OPEN;`. If it errors out, review the specific datafile or log file reported in the failure.

## Domain 2: Tablespaces, Datafiles & Storage Management

### ORA-01653: unable to extend table string.string by string in tablespace string
- **Description:** A table requires more space for data insertion, but the tablespace has run out of contiguous free extents.
- **Probable Causes:** Tablespace storage is completely allocated, datafile autoextend is disabled, or disk filesystem is 100% full.
- **Resolution:**
  1. Add a new datafile: `ALTER TABLESPACE <tablespace_name> ADD DATAFILE '/path/file02.dbf' SIZE 500M AUTOEXTEND ON NEXT 100M MAXSIZE UNLIMITED;`.
  2. Resize existing datafile: `ALTER DATABASE DATAFILE '/path/file01.dbf' RESIZE 10G;`.
  3. Enable autoextend: `ALTER DATABASE DATAFILE '/path/file01.dbf' AUTOEXTEND ON NEXT 100M MAXSIZE 32G;`.

### ORA-01652: unable to extend temp segment by string in tablespace string
- **Description:** Insufficient space in the temporary tablespace during large sorting, hashing, index builds, or aggregation operations.
- **Probable Causes:** Runaway SQL queries performing large cartesian joins, sorting without indexes, or small temporary tablespaces.
- **Resolution:**
  1. Add a tempfile: `ALTER TABLESPACE temp ADD TEMPFILE '/path/temp02.dbf' SIZE 2G AUTOEXTEND ON;`.
  2. Identify and tune high disk-sort SQL queries using `V$SORT_USAGE` and `V$SQL`.

### ORA-01654: unable to extend index string.string by string in tablespace string
- **Description:** An index segment cannot allocate an additional extent in its tablespace.
- **Probable Causes:** Dedicated index tablespace is full, autoextend is off, or storage filesystem has no space remaining.
- **Resolution:** Add or resize datafiles in the affected tablespace or rebuild/coalesce the index: `ALTER INDEX <index_name> REBUILD;`.

### ORA-01110: data file string: 'string'
- **Description:** Contextual error identifying the exact datafile associated with a primary storage error (e.g., `ORA-01157`).
- **Probable Causes:** Secondary stack trace error indicating the affected file identifier and path.
- **Resolution:** Treat this as a diagnostic pointer to inspect the specific file path paired with the leading error.

### ORA-01157: cannot identify/lock data file string - see DBWR trace file
- **Description:** The database background process (DBWR) cannot find or lock a datafile during startup or open operations.
- **Probable Causes:** Datafile was deleted, moved, unmounted from storage (NFS/SAN), or has incorrect OS file permissions.
- **Resolution:**
  1. Restore or move the file back to its correct location with valid `oracle:oinstall` ownership.
  2. If the file was intentionally relocated: `ALTER DATABASE RENAME FILE '/old/path.dbf' TO '/new/path.dbf';`.
  3. If the file is lost and unrecoverable (and belongs to a non-critical tablespace): take it offline and drop: `ALTER DATABASE DATAFILE '/path.dbf' OFFLINE DROP;`.

### ORA-01115: IO error reading block from file string (block # string)
- **Description:** Low-level OS input/output error reading a datafile block.
- **Probable Causes:** Physical storage disk failure, SAN/NAS connection timeout, bad sector, or file corruption.
- **Resolution:** Check OS system logs (`dmesg`, `/var/log/messages`). Run `DBVERIFY` (`dbv file=/path/datafile.dbf`) to test for block corruptions. Restore the block using RMAN block media recovery: `RECOVER DATAFILE <n> BLOCK <m>;`.

### ORA-01144: File size (string blocks) exceeds maximum of string blocks
- **Description:** Attempted to create or resize a datafile beyond the architectural limit of the tablespace block size.
- **Probable Causes:** In a Smallfile tablespace, a datafile cannot exceed $2^{22}-1$ (4,194,303) blocks (e.g., 32 GB for an 8 KB block size).
- **Resolution:** Rather than resizing the single file beyond 32 GB, add additional datafiles to the tablespace or migrate to a Bigfile tablespace (which supports up to 128 TB at 32 KB blocks).

### ORA-01537: cannot add file 'string' - file already part of database
- **Description:** Attempted to add a datafile that is already registered in the control file.
- **Probable Causes:** Typing the wrong filename in `ALTER TABLESPACE ADD DATAFILE`.
- **Resolution:** Check `DBA_DATA_FILES` to verify existing files and provide a unique filename.

## Domain 3: Memory Management (SGA, PGA, AMM & ASMM)

### ORA-04031: unable to allocate string bytes of shared memory ("string","string","string","string")
- **Description:** The Shared Pool or Large Pool ran out of contiguous free memory.
- **Probable Causes:** Shared pool fragmentation caused by high volumes of unshared, non-parameterized SQL (missing bind variables), or undersized `SHARED_POOL_SIZE`.
- **Resolution:**
  1. Flush the shared pool temporarily: `ALTER SYSTEM FLUSH SHARED_POOL;`.
  2. Implement bind variables in application code or temporarily set `CURSOR_SHARING = FORCE`.
  3. Increase `SHARED_POOL_SIZE` or `SGA_TARGET`.
  4. Pin large PL/SQL packages in memory using `DBMS_SHARED_POOL.KEEP`.

### ORA-04030: out of process memory when trying to allocate string bytes
- **Description:** A dedicated server process failed to allocate private memory from the operating system.
- **Probable Causes:** The OS memory limit or swap space was exceeded, or the PGA consumed excessive memory due to heavy client-side operations.
- **Resolution:**
  1. Verify OS limits (`ulimit -a` on Linux, checking `data seg size`, `max memory size`, `virtual memory`).
  2. Check for runaway queries with massive hash joins or PL/SQL arrays.
  3. Tune `PGA_AGGREGATE_TARGET` and `PGA_AGGREGATE_LIMIT`.
  4. Ensure adequate physical RAM and swap space are allocated on the host.

### ORA-00845: MEMORY_TARGET not supported on this system
- **Description:** Automatic Memory Management (AMM) cannot start because the shared memory filesystem (`/dev/shm` on Linux) is smaller than `MEMORY_TARGET` or is unmounted.
- **Probable Causes:** Linux tmpfs/shm partition configured smaller than the target SGA+PGA allocation.
- **Resolution:**
  1. Remount `/dev/shm` with a larger size: `mount -o remount,size=16G /dev/shm`.
  2. Update `/etc/fstab` to persist the change.
  3. Alternatively, disable AMM and switch to ASMM by unsetting `MEMORY_TARGET` / `MEMORY_MAX_TARGET` and setting `SGA_TARGET` and `PGA_AGGREGATE_TARGET`.

### ORA-04036: PGA memory used by the instance exceeds PGA_AGGREGATE_LIMIT
- **Description:** Total PGA usage across all sessions exceeded the hard cap defined by `PGA_AGGREGATE_LIMIT`.
- **Probable Causes:** Runaway processes, runaway parallel queries, or undersized `PGA_AGGREGATE_LIMIT`. Oracle terminated the session using the most PGA to protect host memory.
- **Resolution:**
  1. Query `V$PGASTAT` and `V$PROCESS` to find high-consuming processes.
  2. Increase `PGA_AGGREGATE_LIMIT`: `ALTER SYSTEM SET PGA_AGGREGATE_LIMIT = 16G SCOPE=BOTH;`.
  3. Optimize queries with oversized sort/hash requirements.

### ORA-00821: Specified value of sga_target is too small, needs to be at least stringM
- **Description:** `SGA_TARGET` is set lower than the minimum memory required to allocate essential pools (buffer cache, shared pool, large pool, java pool).
- **Probable Causes:** Manual configuration error during memory tuning.
- **Resolution:** Edit your SPFILE/PFILE to increase `SGA_TARGET` to at least the size recommended in the error message.

## Domain 4: Redo Log, Archiving & Fast Recovery Area (FRA)

### ORA-00257: archiver error. Connect AS SYSDBA only until freed
- **Description:** The archiver background process (ARCn) cannot write archive redo logs, halting all DML activity.
- **Probable Causes:** Archivelog destination or Fast Recovery Area (FRA) is 100% full.
- **Resolution:**
  1. Connect as SYSDBA: `sqlplus / as sysdba`.
  2. Check FRA usage: `SELECT * FROM V$FLASH_RECOVERY_AREA_USAGE;`.
  3. Clear space by backing up and deleting obsolete archive logs via RMAN:
     ```
     RMAN> CONNECT TARGET /
     RMAN> BACKUP ARCHIVELOG ALL DELETE INPUT;
     RMAN> CROSSCHECK ARCHIVELOG ALL;
     RMAN> DELETE EXPIRED ARCHIVELOG ALL;
     ```
  4. Temporarily increase recovery area size: `ALTER SYSTEM SET DB_RECOVERY_FILE_DEST_SIZE = 50G SCOPE=BOTH;`.

### ORA-00313: open failed for members of log group string of thread string
- **Description:** Oracle cannot open or read online redo log group members during log switches or instance startup.
- **Probable Causes:** Redo log files were deleted, corrupted, or access was blocked by file permission changes.
- **Resolution:**
  1. Check `V$LOGFILE` to inspect member status and paths.
  2. If the group is multiplexed and only one member is missing, drop and recreate that specific member.
  3. If an inactive group is entirely missing: `ALTER DATABASE CLEAR LOGFILE GROUP <n>;`.
  4. If the group was `CURRENT` when lost, point-in-time recovery (`RECOVER DATABASE UNTIL CANCEL;`) is required.

### ORA-00333: redo log read error block string count string
- **Description:** An I/O read error occurred while scanning a redo log block during recovery.
- **Probable Causes:** Corrupted physical media, storage bit-rot, or disk subsystem timeout.
- **Resolution:** Restore database from backup and execute point-in-time recovery up to the block prior to the corruption.

### ORA-01624: log string needed for crash recovery of thread string
- **Description:** Attempted to drop or clear an online redo log file that is required for instance crash recovery.
- **Probable Causes:** Attempted cleanup on an active log group.
- **Resolution:** Force a checkpoint to flush dirty buffers and make the log inactive: `ALTER SYSTEM CHECKPOINT;`. Verify in `V$LOG` that the status changes to `INACTIVE` before dropping.

## Domain 5: Undo Management & Read Consistency

### ORA-01555: snapshot too old: rollback segment number string with name "string" too small
- **Description:** A long-running query failed because undo records required to construct a consistent read block image were overwritten.
- **Probable Causes:** Small `UNDO_RETENTION`, undersized undo tablespace, high transaction volume committing frequently, or queries running longer than retention guarantees.
- **Resolution:**
  1. Increase `UNDO_RETENTION`: `ALTER SYSTEM SET UNDO_RETENTION = 86400 SCOPE=BOTH;` (e.g., 24 hours).
  2. Enlarge the undo tablespace and enable autoextend.
  3. Enable retention guarantee: `ALTER TABLESPACE undotbs1 RETENTION GUARANTEE;`.
  4. Tune the long-running query to reduce execution time and avoid full-table scans.

### ORA-30036: unable to extend segment by string in undo tablespace 'string'
- **Description:** The undo tablespace has no remaining space to store undo records for active transactions.
- **Probable Causes:** High-volume uncommitted DML statements, batch jobs lacking intermediate commits, or unextended undo datafiles.
- **Resolution:**
  1. Add space to the undo tablespace: `ALTER TABLESPACE undotbs1 ADD DATAFILE '/path/undo02.dbf' SIZE 2G AUTOEXTEND ON;`.
  2. Identify large transaction sessions via `V$TRANSACTION` and commit or terminate them.

## Domain 6: Locks, Resources & Concurrency

### ORA-00054: resource busy and acquire with NOWAIT specified or timeout expired
- **Description:** An exclusive DDL lock or `SELECT FOR UPDATE NOWAIT` failed because another transaction holds an uncommitted lock on the target table.
- **Probable Causes:** Running DDL (`ALTER TABLE`, `CREATE INDEX`) while DML transactions are executing.
- **Resolution:**
  1. Identify blocking sessions via `DBA_BLOCKERS` and `V$LOCKED_OBJECT`.
  2. Wait for the transaction to complete or terminate the blocking session: `ALTER SYSTEM KILL SESSION 'sid,serial#' IMMEDIATE;`.
  3. Use `DDL_LOCK_TIMEOUT`: `ALTER SESSION SET DDL_LOCK_TIMEOUT = 300;` to allow the DDL to wait.

### ORA-00060: deadlock detected while waiting for resource
- **Description:** Two or more sessions are mutually blocked waiting for resources held by each other. Oracle breaks the deadlock by automatically canceling the statement of one session.
- **Probable Causes:** Unindexed foreign keys causing table-level lock escalation, or application transactions updating the same rows in reverse order.
- **Resolution:**
  1. Inspect the deadlock graph in the incident trace file.
  2. Create missing indexes on foreign key columns.
  3. Standardize row update sequences in application code.

### ORA-00018: maximum number of sessions exceeded
- **Description:** The total count of concurrent active/inactive sessions exceeded the `SESSIONS` initialization parameter limit.
- **Probable Causes:** Connection leak in application connection pools, or sudden connection spikes.
- **Resolution:** Increase limits in SPFILE:
  ```sql
  ALTER SYSTEM SET PROCESSES = 1000 SCOPE=SPFILE;
  ALTER SYSTEM SET SESSIONS = 1520 SCOPE=SPFILE;
