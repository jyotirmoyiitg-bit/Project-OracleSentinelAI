How to run Oracle Sentinel AI

Start the portal, the API, and PostgreSQL from this repository. Settings live in the root .env file. This page lists the parameters and what they do. It does not contain passwords or API keys.

Start Portal Knowledge and RAG .env parameters Checks

Start a local deployment

Use PowerShell from the repository root and the project virtual environment at .venv. Python 3.14 is the intended runtime. Commands are separate lines. PowerShell 5.1 does not accept &&.

  1. Copy .env.example to .env when the file is missing. Fill PostgreSQL, TNS_ADMIN, and the read-only Oracle account. Leave secrets out of source control. .env is git-ignored.
  2. Start PostgreSQL with pgvector, and Redis:
docker compose up -d postgres redis
  1. Install the backend and apply migrations. The schema head includes the knowledge and privileged-operations tables.
.\.venv\Scripts\python.exe -m pip install -e ".\backend[dev]"
.\.venv\Scripts\python.exe -m alembic -c backend\alembic.ini upgrade head
  1. Set SCHEDULER_ENABLED=true when this process should poll Oracle. Collection does not need a language model.
  2. Start the API on port 8000. Settings are read from the root .env no matter which folder the command starts in. Restart this process after a .env change.
.\.venv\Scripts\python.exe -m uvicorn sentinel.main:app --host 127.0.0.1 --port 8000
  1. In a second terminal, start the portal. Vite serves it on port 5173 and proxies /api and /health to http://localhost:8000.
Set-Location frontend
npm ci
npm run dev
Ports. API 127.0.0.1:8000. Portal http://127.0.0.1:5173/. PostgreSQL 5432. Redis 6379. Docker Compose uses image pgvector/pgvector:pg16, database sentinel, user postgres, and password postgres for that local container only.
Configuration table. On startup the API inserts any missing non-secret setting from .env into the PostgreSQL table app_config. A value already stored stays there. An administrator opens a section on the Administration page, chooses Edit, and saves that section. Deployment identity, sign-in, execution, filesystem paths, and the embedding width stay fixed. Passwords, API keys, secret:// references, DATABASE_URL, and REDIS_URL are not written there. Apply migration 0010 with the Alembic command above before starting the API.
Keep execution off. OPERATIONS_EXECUTION_ENABLED and OPERATIONS_EXECUTION_APPROVED stay false. Release 1 stores proposals and does not send a change to Oracle. AI_FALLBACK_PROVIDER stays disabled. A local model failure must not call a hosted model.

Open the portal

Open http://127.0.0.1:5173/. The API document page is http://127.0.0.1:8000/docs.

With AUTH_REQUIRED=true, sign in through the portal. A local account is created from AUTH_BOOTSTRAP_USERNAME and AUTH_BOOTSTRAP_PASSWORD when Active Directory is not configured. The session cookie is sentinel_session. APP_ENV=dev or test lets the local admin principal sentinel choose the local model, Claude, or OpenAI on a Copilot thread. A new Copilot thread starts on the local model when that choice is ready. Production hides the choice and keeps the configured provider.

Copilot explains Oracle concepts and can draft a read-only SQL example. It does not run SQL, PL/SQL, a shell command, or a database change. Measurements come from approved readings. Company requirements come from an approved policy document or a compliance result. The policy is docs/assistant-policy.md.

Knowledge and RAG

Document search already uses PostgreSQL and pgvector. A separate vector database is not required. The scan reads knowledge-intake/ora-19c-manual and knowledge-intake/Policy, splits each file into passages, and stores a local embedding on document_chunks.embedding. Search combines that vector with full-text ranking and returns a citation. The language model is not required for search.

Files under ora-19c-manual are stored with the Knowledge category. Policy files stay the Policy category. Allowed types are .pdf, .docx, .txt, and .md. Other files are left in place. Encrypted, corrupt, scanned, oversized, and over-page files are moved to knowledge-intake/Quarantine. OCR is off, so a scanned PDF is quarantined.

Three ways to run the same scan

On its own. On the Knowledge page, choose Reindex, or send POST /api/v1/knowledge/reindex as an administrator. This works while KNOWLEDGE_ENABLED=false.
From a live PowerShell check. The Phase 5 and Phase 6 launchers call that same reindex API. They keep KNOWLEDGE_ENABLED=false so the timer cannot scan at the same time as the test. A later launcher should call this reindex, not a second indexer.
While the API is running. Set KNOWLEDGE_ENABLED=true. Startup starts a scan every KNOWLEDGE_SCAN_INTERVAL_SECONDS (300 by default). The first scan waits for that interval. A scheduler failure is logged and does not stop Oracle collection.
Page limit is 800. Concepts, Performance Tuning, Data Guard, and Licensing fit. The Administrator's Guide, PL/SQL Reference, ASM, Backup and Recovery, Security, SQL Reference, Database Reference, and Error Messages are larger. A reindex would quarantine those files and move them out of ora-19c-manual. The parser timeout is 30 seconds, which is short for a multi-thousand-page PDF. Raise KNOWLEDGE_MAX_PAGES and KNOWLEDGE_PARSER_TIMEOUT_SECONDS only after you decide those books should be indexed.

The default embedding is the local hasher local-hashing-v1, 128 dimensions. Document text stays on this machine. Remote embeddings run only when EMBEDDING_PROVIDER=remote, EMBEDDING_REMOTE_APPROVED=true, a URL, and a privacy disclosure are all set. The vector width stays 128 until a migration changes the column.

.env parameters

Names match .env.example. Put secret values only in .env or in the variable named by a secret:// reference. A reference such as secret://ANTHROPIC_API_KEY is the name of the variable. It is not the key. An environment variable set in the shell overrides the file.

Checks

Automated tests use temporary databases and do not need Oracle:

.\.venv\Scripts\python.exe -m pytest -c backend\pyproject.toml backend\tests
Set-Location frontend
npm test

Live Oracle checks are separate PowerShell launchers, such as test_real_phase2\Verify_Phase2_Real.ps1 and later phase folders. Run -CheckPrerequisites before a full launch. A full launch stops listeners on ports 8000 and 5173. Do not run two launchers at once. Those scripts keep the language model and privileged execution off for the duration of the check.
