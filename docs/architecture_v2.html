Oracle Sentinel AI

Architecture, version 2 · 15 November 2026 · through Phase 25 · schema revision 0012

One portal and one API process monitor every registered Oracle database through a common read-only account. This version adds WaitDB, the fleet copilot, the agents, stored graph history, and the copilot supervisor with local embeddings, and replaces version 1, which described the system up to GraphDB.

1. Architecture diagram

The API is one process. It holds five capabilities behind one sign-in and permission gate. Oracle is read in two ways, both from the same fixed catalog: inside the API process, or through a short-lived readings server that the API starts for one request.

Designed, not built

These are a design only: a fleet analyst with a daily brief, an Advisor that drafts a proposal from an accepted finding, and the supervisor for the fleet copilot. Privileged execution remains a disabled placeholder.

Boundaries that stay in force

Monitoring stands alone

Collection, rules, incidents, GraphDB, and WaitDB run with the model off and with agents off.

Read-only Oracle

GSYSTEM has SELECT on listed views. The catalog is the only SQL. Operator text and model text never reach a statement.

Evidence before narration

An answer lists its rows. An agent's cause is shown only when the Verifier finds every code, figure, and name in the evidence.

Execution stays off

Proposals can be approved and are not run. Privileged execution answers 501, is audited, and does not open Oracle.
