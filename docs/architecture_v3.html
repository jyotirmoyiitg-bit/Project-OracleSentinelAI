1. Component map

The portal and the API are the two processes that are installed. Everything in the large box runs inside the API process. Each part carries its state on a fresh installation.

2. Components and default state

"Default" is the value on a fresh installation with nothing set in .env. Your installation may differ: a value stored in the portal always wins over .env, and the Admin page shows the current one.

The scheduler is the master for three timers. With scheduler_enabled off, there is no polling, no alert-log reading, no stored graph history, and no automatic investigation, whatever their own switches say.

3. Changing a switch in the portal

Only an administrator sees the Admin link. Every change is written to the audit trail.

  1. Open AdminThe Admin link in the top bar. Scroll to Configuration.
  2. Show the sectionSections are closed. Press Show on Collection, Agents, Language model, Knowledge, Graph history, or Mail.
  3. Edit and SavePress Edit, change the value, press Save. A value out of range is refused with a message.
  4. Restart if neededOnly scheduler_enabled and knowledge_enabled need the API restarted. The rest apply as the table says.

Where the value lives

RuleMeaning
Stored in PostgreSQLA saved value is kept in the app_config table and survives a restart.
The stored value winsAt start the API copies a setting from .env into the table only if it is not stored yet. After that the stored value is used, so changing .env has no effect on a setting the portal already holds.
Fixed settingsA row marked Fixed can be read and not saved. These are set in .env before the first start.
SecretsPasswords and keys are never listed and never stored by the portal.

The top of the Admin page states the current position in words, for example "Scheduler disabled. Knowledge scans disabled." Check it after a restart.

The agents are not a background poller. The Agent Collector stores a snapshot only when someone presses Collect snapshot or when an investigation needs evidence. The continuous polling is the collection scheduler, which uses no model.

5. Turning on a capability

Each list is the shortest path from a fresh installation. All settings are under Admin › Configuration.

Continuous monitoring

  1. Register at least one database (Fleet page, Register).
  2. Collection › scheduler_enabled = true.
  3. Restart the API.
  4. Health, incidents, and forecasts fill in. Graph history starts by itself.

Copilot that answers in sentences

  1. Have Ollama running with a model pulled.
  2. Language model › ai_enabled = true.
  3. Language model › ai_provider = local, and ai_model_name.
  4. Ask on a database. The supervisor is already on.

Agents: snapshots and investigations

  1. Agents › agents_enabled = true.
  2. Open a database: Collect snapshot, or Investigate.
  3. Optional: agent_auto_investigate = true, with the scheduler on.
  4. A written cause needs the local language model. Without it a finding shows the evidence.

Manuals searched by meaning

  1. Put the PDFs in knowledge-intake\ora-19c-manual.
  2. Run the Phase 24 launcher with -ReindexOnly. It selects the embedding model and indexes once.
  3. Optional: Knowledge › knowledge_enabled = true and restart, to pick up new files by itself.
  4. Ollama must be running for a search by meaning.

6. Controls for one database

Most switches apply to the whole system. These apply to one registered database.

ControlWhereWhoEffect
Register and testFleet page › RegisterDBA, administratorA database that the monitoring account cannot reach is not registered.
RemoveFleet page › Remove on the rowDBA, administratorDeregisters the database. Oracle is not changed.
Automatic disableNo control—A database that stays unreachable for 7 days is disabled and an incident asks for its removal.
Agents for this databaseDatabase › Overview › Snapshot panelAdministratorA database can opt out of agents, or have its own packs, retention, minimum gap, and automatic investigation. It cannot opt in while the system switch is off.
Snapshot nowDatabase › Overview › Collect snapshotOperator, DBA, administratorOne logon, up to 15 fixed readings stored.
InvestigateIncident page, or Database › OverviewOperator, DBA, administratorOne run, with its steps shown as they happen.

There is no button to pause polling for one database. Removing it stops all polling for it. Polling frequency per database follows its environment: production is polled twice as often.
